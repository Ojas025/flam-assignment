# B1 — KV cache size and concurrent capacity

**Inputs** (from `model_spec.md`): 28 layers · 8 KV heads · head_dim 128 · fp16 (2 B/element) · 4.2 B params · 1× L4 24 GB · util 0.92 · ~1.6 GB non-KV · `max_model_len` 4096.

## (a) Bytes per token

```
bytes/token = kv_heads × head_dim × 2 (K+V) × layers × bytes/element
            = 8 × 128 × 2 × 28 × 2
            = 114,688 bytes
```

## (b) Max concurrent 4096-token sequences

Using 1 GB = 10⁹ bytes:

```
1 sequence  = 114,688 × 4096          = 0.470 GB
weights     = 4.2×10⁹ × 2             = 8.4 GB
KV budget   = (24 × 0.92) − 8.4 − 1.6 = 12.08 GB
capacity    = 12.08×10⁹ ÷ 469,762,048 = 25.72 → 25 full sequences
```

## Check against `bench_log.csv`

Long-prompt rows use prompt 3584 + gen 512 = 4096 tokens — the length budgeted above.

### 1. Predicted memory matches the log

```
predicted = requests × (prompt_len + gen_len) × 114,688 B ÷ 12.08×10⁹ B
```

- Short-prompt rows are **768** tokens, not 4096; using each row’s own length is why **11 of 13** rows agree (worst gap **0.0046**).
- Worked example (n=24): `24 × 4096 × 114,688 / 12.08×10⁹ = 0.9333` → log **0.93**.
- Rows that predict above 1.00: **1.24** at n=32, **1.87** at n=48. The server cannot hold that; it evicts and pins util at **0.97** — matching the log.

### 2. Preemption counts match overflow

GPU holds **25** full sequences:

- n=32 → **7** extra → log `preempted_seqs = 7`
- n=48 → **23** extra → log `preempted_seqs = 23`

### 3. Breaking point brackets the prediction

- n=24: clean, zero evictions
- n=32: evictions start
- Predicted ceiling **25.72** sits between them

**Conclusion:** Spec alone gives **114,688 B/token** and **25** concurrent 4096-token sequences. The log confirms all three checks.
