# B1 — KV cache per token & max concurrent sequences

Inputs: 28 layers · 8 KV heads ·
head_dim 128 · fp16 = 2 B/element · 4.2 B params · 1× NVIDIA L4 24 GB ·
`gpu_memory_utilization` 0.92 · ~1.6 GB non-KV overhead · `max_model_len` 4096

## (a) KV-cache bytes per token

    bytes/token = kv_heads × head_dim × 2 (K+V) × layers × bytes/element
                = 8 × 128 × 2 × 28 × 2
                = 114,688 bytes

## (b) Max concurrent 4096-token sequences

Unit assumption: 1 GB = 10⁹ bytes.

    1 sequence  = 114,688 × 4096                = 469,762,048 B   (0.470 GB)
    weights     = 4.2×10⁹ × 2                   = 8,400,000,000 B  (8.4 GB)
    KV budget   = (24 × 0.92) − 8.4 − 1.6       = 12.08 GB
    capacity    = 12.08×10⁹ ÷ 469,762,048       = 25.72 → 25 full sequences

---

## Check against `bench_log.csv`

The long-prompt rows run at prompt 3584 + gen 512 = 4096 tokens, exactly
the sequence length budgeted, so each row directly tests the prediction.

**1. Predicted memory use reproduces the logged memory use.**

    predicted = requests × 4096 × 114,688 B ÷ 12.08×10⁹ B

Eleven of the thirteen rows agree with the log once both are rounded to two
decimals; the worst gap is 0.0046. Worked example, the n=24 row:

    24 × 4096 × 114,688 = 11,274,289,152 B
    11,274,289,152 ÷ 12.08×10⁹ = 0.9333   →  log says 0.93 

The two remaining rows are the two where the prediction exceeds 1.00,
- 1.24at n=32, 1.87 at n=48. 
- Demanding more than 100% of the budget is impossible, so the server evicts sequences instead and usage pins at 0.97, exactly what the log records. 
- Those rows confirm the budget from the other side: the prediction says this configuration cannot fit, and the log shows it not fitting.

**2. The preemption counts are the arithmetic remainder of capacity.**

The GPU holds 25 sequences; requests beyond that have nowhere to live:

    n=32:  32 − 25 = 7 extra   →  log: preempted_seqs = 7  
    n=48:  48 − 25 = 23 extra  →  log: preempted_seqs = 23 

Both are exact, not merely close.

**3. The log's own breaking point contains the predicted value.**

n=24 runs clean with zero evictions; n=32 evicts. The true ceiling therefore
lies between 24 and 32, and 25.72 sits inside it.

**Conclusion:** from the spec alone — 114,688 B/token and 25
concurrent 4096-token sequences. The log confirms it three independent ways.
