# B4 — Serving-stack counter confirming the B2 mechanism

- **Counter to pull:** `vllm:num_preemptions_total`, vLLM's preemption counter, assuming the stack is vLLM.
- **Expected value:** 0 across all batch ≤ 24 runs, then ≥ 7 for the batch-32 run and ≥ 23 for the batch-48 run — if the B2 mechanism is correct.
- **Why ≥ and not =:** it counts preemption *events*, not distinct sequences, so it can exceed `preempted_seqs` when a sequence is evicted more than once. A large excess at batch 48 would indicate eviction thrashing.
- **Companion metric:** `vllm:kv_cache_usage_perc` should sit near its ceiling (~0.97) whenever the counter is moving.
- **Falsifiable test:** if the counter stays at 0 while throughput still drops past batch 24, the KV-exhaustion mechanism is wrong and the cause is elsewhere (scheduler overhead, CPU, or the harness).
- **After the fp8 change:** the counter should stay at 0 even at batch 48.
