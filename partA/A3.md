# A3 — corrected cross-language comparison

**Question.** On the A1 corpus, with at least two tokenizers (one Indic-aware) and two units, which single number should drive routing and cost?

**Answer.** **Tokens per parallel sentence** (pooled / micro), measured per tokenizer on the traffic you serve. Parallel sentences hold meaning roughly fixed across languages. Words, characters, and bytes do not.

---

## 1. Setup

| Item | Choice |
|---|---|
| Corpus | FLORES-200 dev — **997** parallel sentences × 6 languages (sample used only as a smoke test) |
| Tokenizers | `gpt2` (v0 baseline), `google/muril-base-cased`, `sarvamai/sarvam-1` |
| Units | tokens per word, grapheme, byte, sentence; tokens per codepoint as a within-language check |
| Aggregation | Micro (pooled) for decisions; macro reported as a check |
| Preprocessing | NFC, collapsed whitespace, casing kept — fixes E1 and E2 |
| Alignment | Script requires equal non-empty segment counts (all six = 997) |

```bash
python partA/updated_fertility.py
python partA/updated_fertility.py --corpus flores
python partA/updated_fertility.py --corpus flores \
    --tokenizer gpt2 --tokenizer hf:google/muril-base-cased --tokenizer hf:sarvamai/sarvam-1
```

Script: `partA/updated_fertility.py` (baseline: `starter_kit/fertility.py`).

## 2. What each unit measures

| Unit | Holds constant? | Use across languages? |
|---|---|---|
| Tokens / word | No — “word” differs by language | No |
| Tokens / grapheme | No — scripts pack differently | No |
| Tokens / byte | No — Indic bytes/char ≈ 3× Latin | No |
| Tokens / codepoint | No | Within one language only |
| **Tokens / sentence** | **Meaning** (parallel translations) | **Yes** |

## 4. Why the units disagree

Under GPT-2, Hindi vs English spans **2.89×** (per byte) to **10.72×** (per grapheme).

Over 997 pairs:

| | graphemes/sentence | bytes/sentence | bytes/grapheme |
|---|---|---|---|
| eng | 126 | 126 | 1.0 |
| hin | 87 | 324 | 3.7 |

Totals: **125,289** and **322,631** bytes across 997 sentences.

- Hindi is shorter in graphemes (**87** vs **126**) but carries **2.6×** the UTF-8 bytes.
- Per-byte ratios flatter Hindi; per-grapheme ratios inflate it.
- Per-word sits in between (Hindi words are shorter: **5.10** vs **5.97** chars/word). MuRIL can look near parity per word (**0.99×**) while still costing **1.16×** per sentence.
- Per-sentence divides by the same 997 on both sides — equal content by construction.

## 5. Recommendation: tokens per sentence (micro)

- Cost is paid in tokens; work arrives as requests → tokens ÷ sentences is the right bill.
- Parallel sentences keep meaning aligned; writing units do not.
- Micro matches a total bill (long lines weigh more). For tokens/sentence, macro = micro by construction.
- “Indic is expensive” is a tokenizer choice: Hindi is **7.45×** English on GPT-2 and **1.16×** on MuRIL.

Compare tokenizers on **absolute** tokens/sentence, not only the ratio to English. Ratios hide English baseline shifts: Sarvam-1 uses **16%** more English tokens than GPT-2 (**30.0** vs **25.8**).

| Tokens saved (ratio) | hin | kan | tam | tel | mal |
|---|---|---|---|---|---|
| gpt2 → muril | 6.3× | 12.5× | 14.3× | 10.5× | 12.6× |
| gpt2 → sarvam-1 | 5.6× | 9.7× | 11.6× | 9.8× | 9.7× |
| sarvam-1 vs muril | 1.12× | 1.29× | 1.24× | 1.07× | 1.31× |

## 6. When to use the other units

| Unit | Use |
|---|---|
| Tokens / word | Within-language checks; auditing v0 |
| Tokens / byte | Encoding efficiency (prefer bytes/token) |
| Tokens / grapheme | Within-script fragmentation |
| Tokens / codepoint | Within-language only |
| Macro averages | Typical-request / latency questions |

## 7. Against REPORT_v0

- GPT-2 on 997 pairs: **6.35×** per word, **7.45×** per sentence, **2.89×** per byte — not one agreed figure.
- MuRIL / Sarvam-1: Hindi is **0.97–0.99×** per word and **1.14–1.16×** per sentence — near parity, not 6×.
- “Property of the script” fails: same text goes from **7.45×** to **1.16×** when only the tokenizer changes.
- Budgeting 6× on top of a dedicated Indic model double-counts.

## 8. Limits

- FLORES is formal translated prose, not production chat.
- MuRIL’s tokenizer is from an encoder model — illustrates an Indic vocabulary, not a served generative model. Re-measure with the serving tokenizer.
- Bengali and Marathi are out of this run.
- Parallel text is approximate meaning, not identical length.
- The 10-line sample gives GPT-2 Hindi at **4.82×** per sentence vs **7.45×** on FLORES — too small for ratios. Isolated notebook runs (E3/E4) show **4.64×** because they still lowercased English.

E1–E6 change one variable at a time (E3/E6 still lowercase English). Absolute figures can differ from this document. E7 / this report apply all fixes together (e.g. Hindi per-word **6.10×** in E6 vs **6.35×** here).
